4A. RETRIEVAL-AUGMENTED GENERATION / MODEL ARCHITECTURE
- The curated knowledge source is knowledge/cv.txt, maintained in GitHub and published to a private Amazon S3 source bucket as cv/cv.txt.
- An automated knowledge publisher uploads the document when its SHA-256 digest changes, then starts and checks an Amazon Bedrock Knowledge Bases ingestion job.
- Ingestion chunks the document (400-token chunks with 15% overlap) and generates 1,024-dimensional embeddings using Amazon Titan Text Embeddings v2.
- Embeddings are stored in a private, dedicated Amazon S3 Vectors bucket and index, separate from the source-document bucket.
- At runtime AWS Lambda invokes Amazon Bedrock RetrieveAndGenerate: the knowledge base retrieves relevant CV passages from the vector store and Amazon Nova Lite uses them to compose a grounded response.
- The generation model is Amazon Nova Lite (amazon.nova-lite-v1:0), using an EU cross-Region inference profile (eu.amazon.nova-lite-v1:0) from the primary Ireland Region, eu-west-1.
- This is RAG and inference against an existing managed foundation model, not custom model training or fine-tuning. Grounding mitigates hallucination but does not guarantee error-free answers.

4B. RUNTIME / SECURITY ARCHITECTURE
- Static HTML, CSS, JavaScript and assets are hosted through AWS Amplify Hosting, with Amazon Route 53 for DNS and managed HTTPS/CDN delivery.
- The first chat question triggers sign-in with Amazon Cognito. The browser uses authorization-code authentication with PKCE; email sign-in is supported and social identity providers are optional.
- Chat requests travel through a separate Amazon CloudFront distribution, then Amazon API Gateway with a JWT authorizer, then AWS Lambda, and finally Amazon Bedrock.
- CloudFront performs request-shape and edge checks. API Gateway validates the JWT. Lambda checks a private origin-verification token, conversation ownership and usage allowances before calling the model.
- DynamoDB uses atomic counters for user and global abuse/cost controls: 10 questions per user per minute, 100 per user per UTC day, 1,000 globally per UTC day and 10,000 globally per UTC month by default. These are limits on model requests, not an absolute AWS billing cap.
- A separate encrypted DynamoDB history table persists questions, answers, timestamps and conversation summaries. Conversation state has a five-minute inactivity boundary; history is retained independently. No access tokens are stored in the history table.
- Amazon CloudWatch captures diagnostic and operational logs; application log retention is 14 days. The design distinguishes operational diagnostics from retained conversation data.
- Output is intentionally limited to concise, CV-grounded answers; authentication, bounded usage and persistence are part of deploying the system responsibly to the public.
